## Grounding and actual profile

PR71 retained the real Engram 3.4.0 mixed-store case: explicit-project search works, but context summaries append foreign project names from global statistics. An explicit selector is not an access-control boundary. That path remains unsupported for client summaries.

`isolated-memory-check.mjs` uses the already installed approved executable, two fresh synthetic stores and the existing bwrap pattern. Each process receives only its own writable home/data and the readonly binary/system runtime. It has an isolated network and cleared environment. Both foreign databases genuinely exist on the host; a separate path-absence control uses the identical mount profile. It is not a filesystem tool injected into the MCP server.

The fresh MCP process retrieves its own decision, cannot retrieve the other store's decision even with `all_projects: true`, and returns context with no foreign project name/title/marker. The reverse direction repeats the controls. After both servers exit, the existing actual prepare-only handoff test demonstrates source-only preparation without those optional servers. This sequence is explicit controlled fallback, not an automatic outage handler or disruption of the user's service.
