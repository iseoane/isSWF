## Problem and evidence

`.audit/verify-action-106-browser.mjs` writes its three screenshot paths before publishing `action-106-browser-result.json` with exclusive creation. During task106, a rerun replaced screenshots and then failed because the result JSON already existed. The original result JSON survived; original screenshot bytes were not preserved. A separate v2 run used distinct paths and passed.

## Impact and proposed check

Reused paths can separate a retained result from its original screenshot evidence. Prefer a unique output directory claimed before the first write. Prepopulate result and screenshot files, rerun verification and assert all original bytes unchanged. A failed run must retain its own partial outputs without modifying earlier evidence.
