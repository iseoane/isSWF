## Acceptance for this cut

- A foreground Node command binds only literal loopback and serves the same canonical status as the coordinator, with no writable state or action endpoints.
- Readable job cards show objective, status, dependency, blocker, next step, requested acceptance, evidence and report provenance.
- Acceptance cards show delivered behavior, demo, checks/review, limits and exact pending decision from the existing curated delivery-summary record. Missing records or sections are explicitly unknown, not inferred from model reports.
- Stable IDs include descriptive objectives and initiative label; no duplicate editable plan, generated status file or mandatory additional role invocation.
- Escape all record text; no HTML/Markdown execution, arbitrary file routes, remote assets or unrestricted origin/host access.
- Tests verify actual HTTP positive/negative cases, malformed/symlink/absent records and unchanged project bytes. An actual own-project page is inspected before delivery.

## Limits

No accept/edit/merge/model buttons, authentication service, command execution, scheduler, full security/client-use approval or all-v1 completion claim. Runtime slot and currentness criteria remain separate work and must stay visible as unknown.
