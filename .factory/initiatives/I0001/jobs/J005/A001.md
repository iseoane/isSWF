## 2. What OPS-07/08/09 and MOD-07 require beyond the above

- One finite, configurable limit shared by workers and panels; initial approved default is two concurrent jobs (`docs/spec-v1.md:217`), panels included (`:219`).
- Capacity is released when a job has no active attempt (waiting-human/blocked without a live attempt), but the reservation is retained while cessation is uncertain: "Si la detención de un intento es incierta, su reserva de espacio y su capacidad potencial se conservan hasta comprobar el cese; marcar el trabajo bloqueado no acredita que su proceso haya parado" (`docs/spec-v1.md:217`).
- A panel entry must be able to use successive slots without deadlock: a panel must not hold a slot while waiting for another entry (`MOD-07`).
- A dependency declares the fact that satisfies it; accepted-but-unintegrated delivery does **not** satisfy a code dependency (`docs/spec-v1.md:299`, `OPS-08`). Cycle detected before execution (`:299`).
- Differentiated reasons with explicit exit conditions for dependency, cycle, capacity and pending decision (`OPS-09`); one block does not cancel compatible jobs (`OPS-07`).

## 3. Exact gaps (nothing invented)

- **G1** no finite slot ledger, so no global capacity.
- **G2** no release transition on verified cessation.
- **G3** declared dependencies never gate execution.
- **G4** no differentiated wait/admission reason plus exit condition exposed.
- **G5** reviewer attempt directory is permanent per logical job, so successive panel slots cannot reuse a slot.

## 4. Minimal design (proposed, not implemented)

Smallest concrete seam = one small dependency-free module plus one operator-store ledger.
No daemon, no scheduler loop, no global lock.

`tools/execution-slots.mjs` (new, no deps):

- `decision({ dependencySatisfied, cycle, freeSlots, pendingDecision })` — pure; returns
  `{ admit: true }` or `{ admit: false, reason: 'dependency' | 'cycle' | 'capacity' | 'decision', exitCondition }`.
  Distinct reason per cause, explicit exit condition (`OPS-09`).
- `reserve({ store, limit, key })` — atomically claims one of `limit` reservation files
  under `<store>/capacity/` using `link` (`EEXIST` → next index; all taken →
  `{ reserved: false, reason: 'capacity' }`). Returns a slot id.
- `release({ store, slotId, cessation })` — unlinks only when `cessation === 'proven'`;
  otherwise keeps the reservation (`docs/spec-v1.md:217`).
- `inspect({ store, limit })` — used/free counts for read-only display; never claims liveness.

Naming is load-bearing: `admission` (existing) = permanent writer exclusion;
`reserve` (new) = concurrency slot. They stay separate files and separate stores so the
existing never-released admission semantics do not change.

Smallest integration points:

1. `tools/isswf-job.mjs run`: after `claimAdmission` and before `mkdtemp`/prepare, call
   `decision` then `reserve`; on no slot throw a `capacity`-classified refusal before any
   side effect. Release on verified terminal cessation using the existing
   `worker-lifecycle.mjs observe` evidence.
2. `tools/reviewer-task.mjs`: a panel entry uses the same `reserve`/`limit`; a panel is a
   sequence of individual reviewer entries, each reserving at start and releasing after
   terminal `result.json`. The per-logical-job directory becomes
   per-slot/per-reviewer-ref so successive entries can run. This is the one structural
   change.
3. `tools/isswf-status.mjs` / panel: expose the `decision` reason, exit condition and free
   slot count read-only, keeping the existing "not liveness" disclaimer. Do not remove
   that disclaimer unless the ledger is actually read.

Explicitly excluded: daemon, general scheduler, cross-store global lock, any claim that
the current cooperative first cut already passes `MOD-07`, and any reopening of the
accepted panel scope.

## 6. Proposed verification map (not executed)

- `OPS-07`: two compatible synthetic jobs isolated; blocking one leaves the other terminal success.
- `OPS-08`: duplicate logical writer blocked at admission; awaiting-human reservation released without marking an integration dependency satisfied.
- `OPS-09`: `decision` returns distinct reason + exit condition for dependency vs cycle vs capacity vs pending decision.
- `MOD-07`: one finite limit shared by worker and panel entries; limit+1 panel entries across successive releases all complete without deadlock.
