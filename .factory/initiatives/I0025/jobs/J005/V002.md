## Blocking source findings

### B1 — Setup specifies an extension path relative to the wrong directory

**Location:** `.agents/skills/isswf-setup/SKILL.md:35`  
**Severity:** blocking · **Confidence:** high

Setup directs adding `tools/token-native-pi.mjs` to project `.pi/settings.json` `extensions`.

Installed Pi 1.5 resolves these entries relative to `<project>/.pi`, not the repository root:

- Installed `dist/core/package-manager.js:747–756` selects the project base directory.
- `:2086–2092` resolves plain extension entries against that directory.
- `:1952–1953` passes that base to path resolution.

Consequently, the stated entry targets `<project>/.pi/tools/token-native-pi.mjs`, rather than the trusted factory source module. Ordinary target projects also need the factory source location resolved separately from their own checkout.

The retained native harness avoids this problem by writing an **absolute** `resolve(repo, 'tools/token-native-pi.mjs')`; it therefore does not verify the documented setup value.

**Recommendation:** specify resolution to the actual trusted source module—using a supported absolute or correctly based path—and test the exact generated settings entry.

### B2 — Event-key deduplication suppresses changed snapshots

**Location:** `tools/token-native-pi.mjs:148`, `:175–186`  
**Severity:** blocking · **Confidence:** high

Persistence returns immediately whenever an event key already exists, without comparing or updating the newly acquired receipt. Settled keys depend only on branch IDs; session-start always uses the same key.

Thus, after recording settlement for branch B, a later supported boundary for B with changed child counters or newly resolved coverage cannot refresh `latest`. Reload/resume also cannot refresh through the already-present session-start key. This conflicts with the requirement to retain incomplete coverage and update it at the next supported boundary.

`tests/token-native-auto-pi.mjs:93–96` checks repeated **unchanged** data only; it does not distinguish unchanged duplication from changed usage at the same boundary.

**Recommendation:** deduplicate identical observations, not all observations sharing an event key. Preserve the initial baseline while allowing changed latest counters/coverage to refresh. Add same-branch changed-counter and unresolved-to-resolved assertions.

### B3 — Atomic replacement does not coordinate ordinary writers

**Location:** `tools/token-native-pi.mjs:140–158`, `:164–168`  
**Severity:** blocking · **Confidence:** high

The sink performs an unlocked read–modify–rename sequence. `inFlight` serializes only one extension instance.

Two instances targeting the same session can both read state S, independently append records, and rename their replacements. The last rename silently loses the other record. Similarly, an unrelated file created after the initial absence check can be overwritten by the unconditional rename.

This is a source-level interleaving, not a claimed experimentally reproduced incident. Atomic rename prevents partially visible JSON; it does not provide the brief’s ordinary-write coordination or no-unrelated-overwrite guarantee.

**Recommendation:** coordinate ownership across instances around the complete transaction, or refuse conflicting ownership safely. Add an interleaved-writer/no-clobber regression; do not imply OS isolation or power-loss guarantees.
