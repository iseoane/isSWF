## Defect and correction

A controlled actual Pi 1.5.0 run through a trusted project-persisted `.pi/settings.json` loaded `tools/token-native-pi.mjs`, captured automatic session-start usage, then failed at process shutdown. Pi raised its documented stale-extension-context error when the late capture completion accessed `request.ctx.ui`; the catch path attempted the same stale access again. This was an observed runtime failure, not an inferred one.

The fix:

- Make session replacement invalidate current ownership and pending work before awaiting configuration. Capture a start epoch and install its config only if that epoch is still current, preventing a late async settings read from reviving a shut-down/replaced runtime.
- Guard both success and failure status updates by the active owner/epoch so a response completing after shutdown does not touch a stale Pi context.

The isolated native synthetic-provider run was repeated after the change: it captured session-start and `agent_settled` events and exited cleanly. This verifies the specific stale-context correction on Pi 1.5.0.
