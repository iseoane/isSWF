## Requirement coverage and application map

1. **Curated Pi/Claude summary contract:** `tools/token-report.mjs` accepts version-1, explicitly bounded `window` summaries with allowlisted metadata, provenance, opaque IDs, actor scope, acceptance count and disjoint counter categories. Manual provenance is host-specific; declared native provenance is labelled but no native schema compatibility is claimed. Unknown keys, free-form/path-like metadata, duplicate row/window identities, cumulative/reset/event modes, and parent/tree plus other rows in a window are refused. EN/ES operations guidance documents this contract and commands.
2. **Deterministic local report and privacy:** CLI accepts explicit `--input` or `--before`/`--after` paths and emits only validated row fields and derived data. Errors do not echo input. Bounds enforced: combined input 1 MiB, 100 rows, 4 KiB/row, 64 KiB/report. No automatic collection, model call, raw session parsing or retained artifact.
3. **Metrics and missingness:** component totals are retained; full processed count appears only when categories are known, otherwise a partial subtotal is explicitly marked. Cache-read share requires known positive denominator; tokens/accepted requires all counter components and positive acceptance. Unknown/unattributed rows remain visible. Comparison checks host/version, model/effort, task class, agent IDs/scope, accepted counts, category availability, and positive baseline; mismatches/zero baseline are not credited as reductions. Cached input is not represented as total-token savings. Reasoning is optional and non-additive.
4. **Behavioral evidence and registration:** `tests/token-report.mjs` uses hand-calculated synthetic Pi/Claude fixtures and covers individual/unattributed rows, exact totals and ratio, matched decrease, scope mismatch, zero baseline/outcome, unknown/malformed/unsafe/overflow counters, duplicates, overlap, excluded fields, unsupported modes, Unicode/space path CLI input, and oversized input. Registered in portable runner and included in discovered test inventory.
5. **Bilingual usage docs and candidate checks:** added the workflow and limits to the canonical EN/ES operations guides. No live host compatibility or actual usage/savings claim is made.
