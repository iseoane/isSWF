## Blocking findings

### B1 — Rolling start comparison makes coherence order-dependent

**Blocking · High confidence**

`tools/token-native-summary.mjs:151–153`; coverage gap at `tests/token-native-claude.mjs:82–85`.

The converter compares each incoming start against the **maximum start seen so far**, then updates that maximum. It does not retain the group minimum.

A static counterexample uses otherwise valid entries sharing source/model/group and end, with distinct categories:

- Starts `1,2,3`: each successive difference is at most one, so all three are accepted; segment start becomes `3`.
- The same entries reversed, starts `3,2,1`: the final comparison is `3−1=2`, so conversion fails.

Thus a group spanning **2ns** can pass the claimed **≤1ns** tolerance depending solely on array order. Four-category ascending starts can similarly span 3ns. Reporting can accept incoherent categories and discard their differing boundaries in the resulting opaque segment.

This is a source-traced counterexample, **not an executed reproduction**. Existing tests cover two start values, not chained starts or permutations.

**Recommendation:** any retained tolerance must validate an order-independent whole-group invariant, with permutation and chained-boundary regressions. This report grants no correction authority.
