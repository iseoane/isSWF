### F2 remains partial — Scalar variant names do not enforce scalar values

**Blocking · High confidence**

- `tools/token-native-claude.mjs:15–26,41,57–59,111–120`
- Coverage gap: `tests/token-native-claude.mjs:32–37`

`canonicalAttributes` checks that the value has exactly one supported variant **name**, but never validates that variant’s payload. Consequently these malformed values pass:

```json
{"stringValue":{"a":"1","b":"2"}}
{"boolValue":{"a":"1","b":"2"}}
{"intValue":[]}
```

1. Set resource attribute `labels` to `{"stringValue":{"a":"1","b":"2"}}`; export cumulative input 11.

3. Both pass line 22. Line 26 serializes their nested objects without normalization.
4. Different resource hashes produce different groups/series. `mergeCumulative` retains both instead of replacing.
5. The unchanged converter produces separate rows; reporting sums input to **22**, not 11. With other categories absent, the complete processed total remains unknown, but input and the known subtotal are inflated.

This is a **source-traced counterexample, not a reviewer-executed reproduction**. The new multi-variant test rejects two variant keys; it does not exercise malformed payloads under a single scalar key.

**Recommendation:** enforce each supported scalar variant’s actual type/representation before hashing; reject objects, arrays and invalid null/type combinations.
