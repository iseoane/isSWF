## Blocking findings

### B1 — Cumulative segments and ordering are discarded
**Severity:** blocking · **Confidence:** high  
**Paths:** `tools/token-native-claude.mjs:23–40,81–89,198`; `tools/token-native-summary.mjs:144–167`

The parser retains only source/model/category/value. OTLP start/end timestamps and native session/resource distinctions are discarded before merging. The merge checks only whether the numeric value decreased.

Consequently, two points with identical dimensions but different cumulative start times and values 11 then 20 are accepted as one series with value 20. A new segment is neither detected nor preserved. Changed-start points with equal values are also silently accepted. Value-decrease rejection does not satisfy r3’s new-start/session-boundary and ordering requirements.

The retained `session` is generated from the launch’s bearer token, not a native metric segment identity. Conversion subsequently drops even that launch identity.

**Required correction:** validate and preserve sufficient opaque series/segment and ordering information before merging. Reject unsupported boundary changes visibly rather than silently treating them as continuation. Add changed-start, equal/nondecreasing reset, replay/out-of-order and multiple-model fixtures.

### B2 — Malformed metric values become valid zero counters
**Severity:** blocking · **Confidence:** high  
**Path:** `tools/token-native-claude.mjs:27–29`

`Number(rawValue)` accepts malformed OTLP representations. Examples include `asInt: false`, `asInt: ""`, and absent `asInt` with `asDouble: null`; each becomes numeric zero and passes the safe-integer check.

This violates schema rejection and can turn invalid/missing data into fabricated zero. Existing tests cover negative values and delta temporality, not these coercions.

**Required correction:** validate the supported OTLP numeric representation before conversion, including canonical integer strings where supported; reject null, booleans, empty strings and ambiguous value fields. Add literal regression assertions.

### B3 — Cancellation does not establish bounded shutdown
**Severity:** blocking · **Confidence:** high  
**Path:** `tools/token-native-claude.mjs:176–187`

After forwarding a signal, the timeout calls `child.kill()`—SIGTERM again—and execution still awaits `close` without a deadline. A child that ignores SIGTERM can therefore keep the helper and receiver alive indefinitely. The later bounded receiver-close timer is unreachable until the child closes.

**Required correction:** implement an explicit, platform-supported bounded cancellation outcome, without claiming descendant cessation. Add a controlled resistant-child fixture and distinguish cancellation, child exit and capture status.

### B4 — Required launch/ingress/platform behavioral coverage is missing
**Severity:** blocking · **Confidence:** high  
**Path:** `tests/token-native-claude.mjs:1–76`

The committed test never launches the helper. It exercises parsing, merge values, configuration reads and persistence. It does not exercise the HTTP boundary, actual disabled-mode receiver/write absence, argument/stdin/stdout preservation, spawn failure, signals, flush/shutdown, or Windows executable-selection mechanics.
