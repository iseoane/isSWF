### B1 — Missing individual counters are rejected instead of retained as unknown

**Location:** `tools/token-native-summary.mjs:112–117`  
**Axes:** Standards and Spec. **Confidence:** high.

The agent adapter accepts `null` only for cache fields. Any absent counter becomes `undefined`, fails `Number.isSafeInteger`, and rejects the entire completed summary.

**Concrete condition:** take the completed agent fixture in `tests/token-native-usage.mjs`, remove `usage.cache_read_input_tokens`, and normalize it. The source necessarily calls `fail()` rather than emitting `counters.cacheRead: null`. Removing input/output counters has the same result.

J004 r2 explicitly requires **“Missing numeric fields unknown”** for individual summaries. The locked declaration establishes the native field names and nullable cache types; it does not override the brief’s required handling of partial supplied numeric summaries.

**Impact:** available individual usage is discarded whenever one category is missing, rather than preserving known counters and exposing incomplete availability.

**Smallest correction:** retain absent numeric categories as `null`, while continuing to reject malformed present values, invalid identities and non-completed statuses. Update the worker’s strict-required-counter claim and any affected guidance.

**Focused verification:** omit each numeric field from an otherwise completed summary; assert the corresponding normalized category is `null`, other values survive, sensitive fields remain excluded, and output stays snapshot-only. Keep negative/unsafe/malformed and async cases rejected.

### B2 — Claude window IDs can exceed the unchanged consumer’s limit

**Location:** `tools/token-native-summary.mjs:154–156`  
**Consumer:** `tools/token-report.mjs:11,22`  
**Axes:** Standards and Spec. **Confidence:** high.

The converter validates `meta.id` as up to 128 characters, then appends `-tree` without validating the resulting ID. The report accepts IDs only up to 128 characters.

**Concrete condition:** use valid same-session start/end summaries and a 124-character alphanumeric `meta.id`. Converter validation passes and emits a **129-character** row ID. The unchanged report rejects that emitted window as `invalid token summary`. A 128-character prefix produces 133 characters.

The existing Pi window path validates its composed IDs; the new Claude path omits that guard.

**Impact:** the converter reports successful conversion but produces a window its intended consumer cannot consume.

**Smallest correction:** validate the composed row ID before returning/emitting the window. Refuse overflow rather than silently truncating identity.

**Focused verification:** demonstrate that a 123-character prefix produces a consumable 128-character ID, while longer prefixes fail conversion cleanly. Exercise the real report consumer.
