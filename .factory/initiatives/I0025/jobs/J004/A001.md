## Implemented behavior

- **Claude cumulative tree windows:** the converter now accepts explicit start/end final-result summaries when they have the same native `session_id`, identical sorted model identities, and a known caller-declared host version. It compares counters per model, rejects decreases and mismatched sessions/models, preserves any category delta as `null` if either boundary is missing, and emits exactly one inclusive tree row. The shared acceptance count is therefore represented once; native per-model totals and parent-only `usage` are not added. A one-result input—including a resumed result—remains `mode: "snapshot"` and the unchanged report consumer rejects it. Unknown-version Claude windows are refused.
- **Individual completed AgentOutput snapshots:** an explicit `{ "agentOutput": ... }` input is accepted only for `status: "completed"` with required numeric input/output and cache counters in the source shape. Nullable cache fields remain unknown. The opaque hash of `agentId` and a fingerprint of available model identities are retained; prompt, content, worktree, and raw agent identifiers are not. Async/incomplete launches are rejected. This is a separate individual snapshot, not an inclusive tree contribution, accepted outcome, window, or per-resume attribution. No arithmetic combines it with a tree summary.
- **Privacy/consumer contract:** the existing `tools/token-report.mjs` was not changed or relaxed. Tests pass normalized Claude windows into the real report consumer and assert literal totals. The single tree row avoids overlap with individual attribution.
- EN/ES operations guidance now describes the window guards, single-snapshot behavior, individual AgentOutput form and limits equivalently.
