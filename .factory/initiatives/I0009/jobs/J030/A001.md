The Claude parser accepts one successful nonempty terminal result; duplicate results fail. Missing terminal state, malformed events, nonzero exit, timeout, and stop cannot become success. It does not reject every non-result event after a terminal result, so do not claim that stronger ordering guarantee.

Preflight has a separate maximum of five seconds per local probe and 256 KiB output (`external-cli-preflight.js:5–6, 91–109`). Test preflight separately from run-time deadlines.

Windows uses `taskkill /T /F` plus the process controller (`external-cli-runner.js:105–112`). Unknown cleanup proof becomes a failure explicitly on non-Windows at lines 386–388; this does not establish equal Windows descendant-cessation assurance.

### Account, settings, and cost boundaries

The adapter environment allowlist includes API keys/tokens, alternate endpoints, OAuth tokens, Bedrock/Vertex/Foundry selectors, cloud credentials, and proxies (`claude-code-adapter.js:14–47`). `externalEnvironment` copies allowed inherited values (`external-cli-runner.js:44–63`).

Therefore **native Claude execution is not automatically subscription-only execution**. No-tools mode and `plan` permissions do not prevent:

- a paid-key or alternate-provider route;
- trusted user hooks executing;
- user settings choosing an endpoint or other behavior;
- host startup side effects.

Before any live call:

1. Establish the executable and its non-wrapper topology through authorized passive inspection.
2. Establish trusted user settings/hooks through an approved, sanitized configuration assessment—not credential-file collection.
3. Establish a supported per-process environment/account boundary that excludes paid-key/alternate-provider bypasses without changing global state.
4. Confirm that required suppression of update/telemetry/network side effects is actually supported. The current adapter allowlist does **not** carry the suppression variables used by repository host fixtures.
5. Retain only sanitized presence/route/trust conclusions, never values.

The supplied profile exposes no demonstrated per-launch arbitrary environment override. Do not invent one. If the existing host cannot enforce the required boundary, block the live call and identify the smallest change at the owning host boundary; do not disguise it with a shell launcher.
