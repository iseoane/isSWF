## Conclusion

J029 remains necessary, but it is not a missing migration API. Public migrate-state/recover-state and guarded owner identity already exist. The missing acceptance is native portable directory publication and real interrupted migration-owner recovery through the installed public launcher. Existing synthetic/bootstrap recovery tests are useful, not proof of those claims. Keep two functional units: native normal migration first, then actual interruption recovery after its publication contract is stable.

## Recommended acceptance plan

### Unit 1: normal portable installed migration

Use disposable repositories/stores and an exact released candidate. Native Linux/Windows inspect→migrate-state→identical repeat must preserve inventory bytes, historical references, pins/models and applicable modes, with exactly one active root. Cover dirty/untracked state, changed inventory, dual roots, unsafe entries, existing claims/journals and uncertain ownership. Give directory-open/sync failure controls before changing portability code; keep Linux errors fatal and document Windows's narrower durability. Share runtime evidence across Pi/Claude consumers, no redundant model calls.

### Unit 2: actual interrupted-owner installed recovery

Only after Unit1's publication policy is stable, pause a real migration owner at deterministic bounded claim-before-journal, pre-rename and post-rename points in disposable fixtures. Terminate that exact process, await terminal status, establish start/boot identity cessation through the public launcher and call installed recover-state. Verify exact inventory and one active root; live/unknown/malformed identity, drift, claim/journal disagreement and competing state remain nonzero refusals preserving evidence. Distinguish genuine Node and compiled Bun journeys and native Windows/Linux observations. Never force unlock or infer cessation from a timeout.

## Costs, stopping conditions and recommendation

No dependency on J028 or parked isolated executor is justified by current code. No runtime redesign, new dispatcher or broad portability rewrite is needed. A bounded fixture/portability unit has useful value; uncontrolled repeated kill loops, another store and broad host-model testing do not. Stop if native Windows cannot be run or owner identity is unavailable; keep that acceptance blocked instead of weakening it. Data-loss/false-cessation risk warrants independent exact-candidate judgment with retained real interruption receipts before technical closure.
