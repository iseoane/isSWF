  - Known limits (also in the operations docs):
    - Only `git commit` is checked. `commit-tree`, `update-ref`, `merge`, `rebase`, `cherry-pick`, `revert`, `am`, `stash`, `pull` and `reset` are not.
    - Aliases, scripts, `eval`, `bash -c` and variable-built commands are not parsed. Pi `!` commands are not guarded.
    - A peer switch inside the same chained command is not seen. Parallel Pi calls can interleave.
    - The first command of a session that runs after a peer switch is not refused, because the first look adopts the branch.
    - Fail-open: an unreadable branch, state or guard fault allows the command. Unreadable directories (variables, `~`, `-`, quoted text with spaces, MSYS `/c/...` paths) run unchecked.
    - `git branch -m`, or a rebase/bisect detached HEAD, makes the next commit look like a switch.
    - A child that runs in its own worktree is judged against the session directory unless its command names the directory. `--git-dir` pointing at a linked worktree's private directory reads the main checkout.
