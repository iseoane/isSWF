# Retrospective

Run this profile after every completed feature or bug, and when the operator explicitly closes a work session. A chat ending is not a work-session close. A session review covers the authorized project work since the previous retrospective, including work still in progress, even when no incident or improvement is apparent.

Read [the procedure](references/retrospective.md) and use `.factory/templates/retrospective.md`. Inspect only evidence owned by the authorized project and within the current grant. Do not read broad session logs, other clients' material, or unrelated work. Never infer whether a worker is live from a saved status.

Return findings and proposed improvements as local drafts. A proposal, including a factory improvement issue draft, may be passed to triage but does not authorize implementation, an actual tracker issue, network activity, or a new grant. Do not edit `AGENTS.md`, skills, or active-job instructions. Do not stop active workers or rewrite pinned briefs. If analysis fails, report the reason and leave the retrospective pending; this does not block delivery that is otherwise verified.
