# Once-per-session local version advisory

Read this reference on the first activation of the [coordinator skill](../SKILL.md) in a Pi or Claude Code session. Later activations in the same session skip it.

Retain the `isSWF loaded-resource release version` line of the coordinator skill from the skill text loaded into this session; do not reread the mutable skill file to recover the running version. This advisory reports installed-package version metadata; it does not certify a published release, publisher authenticity, or loaded-file integrity. Treat the captured literal as the running package version only when the host-provided skill/plugin root is positively identified as an installation managed by that host. A source/development checkout used in place (including a Claude `--plugin-dir` source override), an unregistered path, or an ambiguous root leaves the running version unknown. Do not invoke release/package verifiers or execute package code for this advisory. This informational comparison does not change release verification or installation security contracts elsewhere.

Limit installed candidates to the local inventory visible to this host, user and current project: Pi's `pi list` user/project registrations and their reported installed paths, or Claude Code's `claude plugin list --json` user/project/local records and reported versions/install paths. Run either inventory command only when it is side-effect free and consistent with the inspection rule in [explicit host-native package update](../../isswf-setup/SKILL.md#explicit-host-native-package-update); otherwise the in-scope inventory is unavailable. Do not inspect other projects or claim a machine-wide newest version. Apply the same managed-installation versus source-override distinction to every candidate as to the running identity. For each in-scope isSWF record, establish host-manager ownership, its source type and actual installed root/package identity before reading its declared complete numeric package version as informational installed metadata. Pi-managed npm/Git installations may qualify; a registered local development/source directory loaded in place does not qualify merely because the manager lists an existing path and manifest. Exclude positively identified development/source overrides from the candidate maximum. For Claude, distinguish a development override from an installed local artifact using its installation/source evidence; `readFromFolder` alone does not prove either classification. A configured registration or existing path alone is insufficient; ambiguous ownership or source classification makes the relevant installed-version evidence unknown. Do not scan arbitrary directories or caches, fetch from a provider/registry, or infer a version from the host application's own version. Include every in-scope installed candidate and select their numeric maximum. If any relevant record is missing its path, unreadable, malformed, mismatched, or ambiguous, or if the in-scope inventory is incomplete/unavailable, the newest in-scope version is unknown; do not discard that record and call a lower version newest.

Compare only complete numeric `major.minor.patch` versions. On the first activation, if the known maximum in-scope installed-package version is newer than the captured running version, emit one informational line: `isSWF package version notice: running v<RUNNING>, newest package reported installed for this host/user/project v<INSTALLED>. This is package metadata, not release verification. Run isswf-setup to review.` If both versions are known and equal or the installed version is older, emit no advisory. If either side is unknown, emit one line naming the unknown side and stating that up-to-date status is not verified. Do not update, delete, or otherwise alter anything.

Mark the advisory as evaluated in this session's conversation context and preserve that marker in any compaction/session handoff. Repeated activation must not reread versions, refresh the advisory, or repeat the line. If you cannot establish whether this session already evaluated it, do not emit a duplicate notice. This is an instruction-level advisory, not a host callback or guarantee of model adherence.
