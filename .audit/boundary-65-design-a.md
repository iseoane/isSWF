# Task 65 — host model, sandboxed tools (design only)

**Recommendation.** Use Pi 1.2’s SDK in one small Node `.mjs` runner, not RPC-with-host-tools and not a new agent framework. Keep Luna High’s `ModelRuntime` and provider request in the trusted host process; expose exactly one model tool (`bash`) whose `BashOperations.exec` dispatches to the existing bubblewrap namespace and task fixture. `createBashToolDefinition(cwd, { operations })` is explicitly pluggable, so this is narrower than forwarding Pi’s general built-in host tools and avoids implementing a shell schema (`dist/core/tools/bash.d.ts:35–78`). Permit no other tool, command, extension, MCP, skill, prompt-template, context-file, or resource discovery. Use explicit SDK `tools: ["bash"]`, custom `ResourceLoader` returning empty resources and a fixed system prompt, in-memory settings/session; set retries and compaction off. SDK allows each boundary to be supplied (`docs/sdk.md:96–119`; `dist/core/sdk.d.ts:10–67`; `dist/core/resource-loader.d.ts:32–75`).

**Credential/model boundary.** Do not start or prompt a model until the parent selects Luna High. Resolve exactly that provider/model in `ModelRuntime`, set the selected thinking/reasoning level explicitly, and record actual `session.model` and `session.thinkingLevel` plus assistant usage/stop metadata. Missing model/auth or mismatch is a hard failure: no availability-based selection, fallback, or retry. The host model runtime alone resolves normal credentials; never read credential files/values or pass keys, auth paths, host `HOME`, or inherited environment into bwrap. Give bwrap a scrubbed spawn environment; its payload gets only fixed non-secret sandbox variables (`--clearenv`). Do not expose Pi `PI_*` session environment. The trusted model supervisor remains outside bwrap; only the tool runner and fixture are sandboxed. Provider input is restricted to the authorized task fixture, fixed instructions, and bounded tool outputs—no secret context. Tool stdout/model text and task files can still leave through the provider/model response, so fixture content must be authorized and secret-free; this is not output confidentiality.

**Boundary enforcement / audit.** Validate the tool’s command and timeout at the host API boundary; pin cwd and the same namespace/mount policy as #64, never accept caller-supplied mounts, environment, host paths, or bwrap options. Keep filesystem/network denials as OS controls, not prompt rules. Return only bounded stdout/stderr; do not persist raw command/output logs or spill full output to host temp files. No other host reads are reachable through the bridge. Same actor must first prove a positive write/code change inside the fixture, then prove canary host-path/symlink reads and writes, network, and secret-env denial while the canary remains unchanged. Distinguish ENOENT (path absent) from EACCES/EROFS and report exact evidence; bounded time/output and cleanup on all exits.

**Grounding and limits.** Worker contract requires grounded, scoped work and bars unapproved installs, Python, network, global config, commits, and subagents (`.agents/roles/worker.md:5–36`). #64 already supplies the namespace/mount baseline (`.audit/probe-64.mjs:62–74`) and explicitly leaves provider/auth bridge, FD/root-path exhaustiveness, resource limits, lifecycle/recovery, multiwriter exclusion, and production security unproven (`.audit/probe-64-closure.md:21–23`). Pi’s security doc warns the SDK process/extensions retain host permissions; context discovery is not isolation (`docs/security.md:1–20`).

**Smallest verifiable proposal:** one Node audit runner, at most one companion fixture/instrument file. Reuse the #64 disposable canary pattern; keep a separate sum/check fixture independent of the parent selection tests. No actual model call in this design task; a later parent-approved run must record exact Luna High identity/reasoning metadata and have no fallback. Unknown: provider-specific Luna High ID/effort/auth availability, bwrap limits and same-namespace lifecycle semantics. Not production/client-ready; no real credentials, credential inspection, network/install, Python, extra agents, or commits.
