# Lifecycle 44 — worker-owned detached attempt

**Design only; no implementation or model call.** At `f1316072c5447e857fe16caa4804990ac8e6d741`, `.audit/lifecycle-44-acceptance.md` requires a worker to outlive its initiator, fresh-reader evidence, conservative duplicate blocking, durable results, and bounded recovery. `.audit/lifecycle-44-grounding.md` identifies the actual seam: `.audit/boundary-65.mjs` creates a bounded Pi SDK task/session, but does not supervise durable work. `.audit/lifecycle-44-detach-feasibility.mjs` proves only that a detached local Node child can outlive its launcher. The package discovery in `tools/factory-package.mjs` is not worker transport.

## Choose one detached worker, no supervisor

Extend the eventual local authorized worker entry point as one small Node module, `tools/worker.mjs`, with `launch(grant)` and `read(attemptId)` paths; its child-only `run(attemptId)` path uses the existing bounded worker adapter. `launch` validates trusted authorization and pinned inputs, claims an attempt directory exclusively, spawns one detached child with ignored stdio, and exits. A fresh `read` validates records and checks actual process identity; it never launches, repairs, signals, or retries. No daemon, queue, global service/configuration, new dependency, or framework.

Caller: `node tools/worker.mjs launch <authorized-grant-ref>` then, in any fresh CLI/chat, `node tools/worker.mjs read <attempt-id>`. Attempt path: `.factory/jobs/<job-id>/runs/<attempt-id>/`. Claim by exclusive directory creation makes repeated launch of the same attempt fail closed, including after terminal completion.

## Records, ownership, publication

`dispatch.json` is immutable and coordinator-created before spawn: `{schema, jobId, attemptId, actor, authorizationRef, implementationSha, inputCheckpointSha, briefPath, targetBaseSha, checkout, adapter}`. Validate full SHA/path pins at launch; later criteria/config changes do not alter this attempt. Do not copy secrets into records. The worker exclusively owns the existing durable-work `A001.md` technical report (`docs/durable-work.md`, `docs/templates/attempt.md`); it does not own coordinator acceptance. Separate lifecycle metadata is machine-readable: worker atomically publishes `owner.json` `{schema, attemptId, pid, bootId, procStartTicks, executable, nonce}` after startup, then publishes `terminal.json` `{schema, attemptId, ownerDigest, outcome, exitCode, finishedAt, reportPath, reportSha256, diagnostics}` only after atomically publishing `A001.md`. Use bounded diagnostics; temp-file + same-directory rename, with file and directory sync where supported. Terminal evidence is structured and digest-bound, not Markdown status alone.

Reader states: valid terminal record + matching report digest → `terminal` (technical outcome remains distinct from coordinator acceptance); matching live owner → `running`; absent/malformed/torn records, owner mismatch, or no terminal and no matching live owner → `unknown` / `interrupted-unknown`. Unknown blocks another writer. Never turn a vanished process into success or automatic retry. Recovery is inspection of partial checkout and records; only the coordinator may authorize a distinct new attempt after reconciliation.

On Linux, identify a live process by PID **plus** `/proc/sys/kernel/random/boot_id`, `/proc/<pid>/stat` start-time ticks, executable identity, and attempt nonce in its arguments—not PID alone. Recheck the tuple before reporting live; never signal based on it. This `/proc` implementation supports the first Linux host only; other OSes must report unsupported/unknown, not emulate proof.

## Crash windows and proof

A crash after claim but before spawn leaves an unowned claim: unknown, permanently blocking that attempt. Crash after spawn but before `owner.json` is likewise unknown; a reader must not guess or kill a child. A crash before terminal rename leaves partial output and no terminal success; a torn temp is ignored, never promoted. After terminal rename the report and digest already exist. Bounds (wall time, tools/calls, output/diagnostics) come from the existing bounded adapter; lifecycle itself adds no retry loop.

Prefer this over a separate supervisor, which adds another owner/state machine and recovery failure point without avoiding ambiguous spawn/ack crashes. Verify later with rerunnable disposable real-process fixtures: launcher exits while child continues; success and nonzero failure; owner/controller crash and fresh-reader recovery; repeated launch while live/terminal; PID identity mismatch; corrupt/torn records; bounded timeout and cleanup. Assert actual process facts and atomic files. Deterministic fixtures prove lifecycle mechanics only—not Luna/native model integration, sandbox enforcement, or broad #44 completion. Any later model path must use the explicitly authorized local worker route and report actual model metadata; no model call is authorized by this design.
