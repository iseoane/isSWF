# Model routing

This guide defines routing only for explicitly selected retained legacy-executor assignments. Its `models.json` route source is not a current Pi or Claude model-selection authority: each host's supported native configuration owns current selections (see [Pi](../.agents/hosts/pi.md) and [Claude Code](../.agents/hosts/claude-code.md)). `.factory/models.json` remains a packaged legacy payload; initialized legacy projects retain their existing state-directory copy and callers. Do not copy native choices into it or use it as fallback. The coordinator applies the legacy rules below. The text-only legacy researcher caller implements the bounded path at the end; this guide and route membership are not authorization grants.

## Own methodology pins in installed releases

New complete releases pin `methodologySha` to their committed source revision and use the English profiles and references verified by the release receipt. Preserve historical source payloads at their original SHA; they are provenance, not instructions silently substituted for the selected release. Installed worker preparation accepts only the receipt's methodology pin. The source-checkout worker path retains its legacy fixed baseline. Existing attempts keep their original runtime and methodology identities; neither translation nor a global package update changes them. Project briefs, model configuration, and target code remain separately pinned Git inputs.

## Before dispatch

Read the whole configuration from the pinned input checkpoint and record its path and full input Git SHA in the attempt. Resolve the complete ordered route, then validate that the role exists and every tuple is permitted by the trusted grant. An unknown role blocks unless the trusted grant explicitly supplies an approved whole-route override; that override cannot widen the grant. Do not preflight runtime availability or effort compatibility for alternate tuples. Before using a selected tuple, confirm its runtime support, requested-effort support, and current availability from runtime evidence. A confirmed unavailable or quota-exhausted tuple may advance only under the transition rules below. Unknown availability or failed compatibility checks block use of that tuple rather than silently substituting a model. Model routes are independent of transport. A configured role does not establish executable support for that role; use only a supported execution path verified for the assignment.

Resolve one complete ordered route, without merging tuple fields across destinations. Precedence is an explicit whole-route job override, then the configured role route, then a project default if one exists. No project default is configured. An unknown role blocks unless the trusted job grant explicitly supplies a complete approved route override. An override cannot widen that grant. Configuration membership does not authorize an actor, additional worker, review, cost, or action.

Read route values from the exact pinned model configuration, not a model name copied from this guide. A one-entry array has no alternate. An additional-review route is used only when the job explicitly assigns that role; it is never an automatic fallback. Record the ordered route and selected destination in the attempt. Record requested and observed actual model and effort metadata, availability and effort evidence, and each route transition with its reason. Record an account or subscription alias only when the operator supplied a real alias; provider names are not account aliases.

## Route transitions and replacement

Advance only to the next tuple in route order when the selected destination is confirmed unavailable or its quota/capacity is exhausted. Before using that next tuple, confirm the prior writer stopped and reconcile its identity, task, ownership, partial work, and total actor grant. Then verify the next tuple is approved by the trusted grant and currently supported, effort-compatible, and available. Unknown availability, unsupported or incompatible effort, unknown identity or state, an active writer, or an unresolved grant blocks at that tuple; do not skip ahead. An exhausted route blocks. Test failures, review findings, poor output, and unfavorable results are not routing failures and must not trigger another model. Do not infer compatibility, availability, quota, or actual model identity from configuration values. Route membership does not authorize another actor, and isolation or reported completion does not prove a process stopped.

A changed configuration or default affects future attempts only. Preserve each attempt's pinned configuration path, full input Git SHA, resolved ordered route, selected destination, observed actual metadata, and transition reasons. Do not resolve an existing attempt against the latest configuration. Do not embed a would-be commit SHA in the artifact whose commit it would identify.

## Dispatch a text-only researcher

Use `tools/researcher-task.mjs` only for research over an explicitly supplied, pinned source bundle. This caller has no tools, agent sessions, extensions, discovery, or target writes. It does not replace research that needs interactive code navigation or network access. The worker's Luna/high route and normal job runner remain unchanged.

Commit a research job with `version: 1`, `logicalJobRef`, `briefPath`, `sources` (target Git paths), `targetRepo`, `targetBase`, `sdkPath`, and `models: {sha, path, sha256}`. The brief is read at the document input checkpoint; target sources are read at the separate target base. The pinned model document supplies the complete researcher route. Live defaults do not alter it.

The operator-owned grant must be outside both repositories, the runtime source, and the private store. It binds `version: 1`, `role: "researcher"`, `logicalJobRef`, `grantRef`, canonical `project`, `inputSha`, `jobPath`, `jobSha256`, `targetRepo`, `targetBase`, `store`, exact `callerSha256`, and the complete `approvedRoute`. Require explicit integers for `totalAttempts`, `retryBudget`, `deadlineMs`, `outputBytes`, and `maxOutputTokens`; there are no defaults. Both attempt and retry budgets are cumulative across the entire route and never reset at a destination change. It must allow the result artifact, explicitly allow provider calls, prohibit additional API costs, approve `temporaryUnavailableStatuses: [503]`, and supply an opaque host `authPath` plus the approved SDK entry digest `sdkEntrySha256`. The JSON flags are `allowResultArtifact: true`, `allowProviderCalls: true`, and `apiCostsAllowed: false`. Unconfirmed subscription use blocks. The SDK confirms subscription status only for supported OAuth providers, not for API-key plans such as OpenCode Go. For those plans, a trusted grant must separately supply `subscriptionAttestations: [{provider, coversCallsWithoutAdditionalApiCost: true, reference}]` after the operator confirms the configured account's coverage. An actual operator-supplied `accountAlias` is optional; provider names are not invented account aliases. Claims and outcomes label this evidence as an operator attestation, not SDK verification. Missing or uncertain coverage still blocks. Paid API ceilings are not implemented.

Invoke the reviewed caller only under that concrete grant:

```sh
node /absolute/fixed-isSWF/tools/researcher-task.mjs \
  --project /absolute/project --input-sha FULL_SHA --job research/job.json \
  --grant-file /absolute/operator/research-grant.json \
  --store /absolute/private-research-store --mode real
```

The store must already exist outside the repositories. A write-once logical-job directory prevents replay after any result or interruption. A random opaque UUID is persisted as `sessionId` in the binding and passed through the SDK stream options. It is reused across retries and approved destinations within that run; separate runs get different IDs. It is provider-transmitted affinity/cache metadata, not a project path, user identity, or a recoverable agent session. Each numbered claim is synced before the call and consumes the cumulative total across retries and destinations. A missing result never releases a claim. This caller does not recover or automatically resume research calls; stop and inspect its records. The result contains the findings, pinned route, selected tuples, attempt counts, and transition reasons.

One HTTP request is allowed per SDK attempt, with SDK retries disabled and SSE transport selected. A 503 permits only the explicitly budgeted retries, then the next approved tuple after the previous stream ends. An unrecognized 429, unknown error, unfinished stream, unsupported effort, missing auth, test failure, or poor findings cannot trigger fallback. Deadline expiry consumes the uncertain invocation and blocks continuation.

Automatic quota handling is limited to one known OpenCode Go contract: HTTP 429, selected provider `opencode-go`, top-level `type: "error"`, and `error.type: "GoUsageLimitError"`. `RateLimitError` is not that quota signal. The classifier does not prove that the current service emits this envelope. Other formats, providers and codes remain unknown and block. The caller observes a cloned response under the same deadline and retains at most 8192 bytes for parsing. It cancels oversized observations; this does not cap the underlying fetch's chunk allocation or the SDK's body read. The original response remains available to the SDK, and only the finite error code enters the quota record. Once the previous stream ends, a recognized quota error advances without retry, preserving the total attempt budget. No error prose, account metadata or response headers enter the quota record.

A trusted grant may still supply `authoritativeQuotaEvidence: [{tuple: {model, effort}, confirmedExhausted: true, reference}]` for an exact approved tuple. This records operator-supplied evidence and consumes a conservative attempt slot without sending that tuple a request. It is not a claim that the SDK detected quota exhaustion. Without this explicit evidence or the recognized Go envelope, 429 stays unknown.

Run `node tests/researcher-quota-fallback.mjs` for the portable quota transition and blocking controls. An optional absolute SDK package path after the source root exercises the primary SDK with synthetic auth and transport, while the alternate stays injected. Neither mode calls the service.

## Dispatch an independent reviewer

Use `tools/reviewer-task.mjs` from a fixed source checkout for one independent review of a committed candidate. This native caller does not use an external dispatcher. Its default is text-only. An optional, explicitly granted workspace runs bounded read-only checks before the model call. Neither mode broadens the worker route, implements all role delegation, accepts arbitrary snapshots or gives the model workspace tools. The reviewer must state missing evidence and unrun relevant checks; a complete model response is not a passing review or acceptance. The coordinator assesses Standards and Spec separately.

Commit a job containing `version: 1`, `logicalJobRef`, `implementerRef`, `briefPath`, canonical `targetRepo`, full `targetBase` and `candidateSha`, `contextPaths` naming explicit standards/context at the candidate, `methodologySha` in the factory source, `sdkPath`, and `models: {sha, path, sha256}` in the project. The candidate must descend from the base. The caller supplies the full binary diff and base/candidate text for every changed regular file, plus context and own pinned reviewer references. Non-UTF8, unsupported entries, excess changed/context files or a combined evidence/instruction bundle above the granted input limit block. Defaults remain 20 changed files, 20 context files and 64 KiB. An explicit external grant may set positive integer `maxChangedFiles` and `maxContextFiles`, each at most 64, and `inputBytes` up to 1048576 for a coherent larger review. Increasing the byte budget does not increase either file budget. Nothing is silently truncated. These transport ceilings do not prove that the selected model can accept the resulting token count; model compatibility, subscription preflight, one attempt, deadline, output caps and no-fallback rules still apply.

The effective evidence limits enter both the supplied authorization and the retained binding. Evidence persistence and readback alone allow JSON-serialization overhead, bounded to six times the granted input bytes plus 1024 bytes, with the existing 256000-byte minimum envelope. The original combined prompt/instruction byte limit remains enforced on readback. Other grant, binding and result JSON bounds are unchanged. This prevents a larger review from failing only after claiming its execution because the evidence artifact exceeded the old storage envelope. This is bounded evidence review, not a claim of complete source discovery.

To avoid duplicating the full base text, explicitly set `evidenceMode: "candidate-and-diff"` in both the assignment and grant. This mode supplies each full candidate file and the unchanged full-index binary diff, including old changed lines and deleted-file contents. It does not supply a separate full base copy. The default `base-and-candidate` representation remains unchanged. Unknown or mismatched modes block preparation, and the granted input limit still applies. Select context needed to understand the change in either mode.

Before preparing the assignment, identify the claims the reviewer must assess and include their existing committed evidence in `contextPaths`, not only coding standards. Unchanged prior delivery/review records are valid candidate-side context even when absent from the diff. The caller reads their candidate Git blobs, never dirty working-copy replacements. A missing selected path blocks preparation before an attempt or SDK call; omitted context cannot be discovered by this tool-free reviewer. Inspect the prepared prompt/bundle locally for coverage and size before requesting a real-run grant. Git-pinned text is evidence supplied, not independent proof that its historical assertions are true. If a necessary record is unavailable or cannot fit, report the dependent conclusion as inconclusive rather than adding a retry or claiming the reviewer inspected it.

The trusted external grant binds `version: 1`, `role: "reviewer"`, `project`, `store`, `inputSha`, `jobPath`, `jobSha256`, `logicalJobRef`, `targetRepo`, `targetBase`, `candidateSha`, `grantRef`, matching `implementerRef`, distinct `reviewerRef`, exact `callerSha256` and shared researcher `backendSha256`, `allowResultArtifact: true`, explicit `allowProviderCalls`, and `apiCostsAllowed: false`. Actor identities and the grant's provenance remain operator attestations, not authenticated by the caller. Supply the exact pinned one-entry canonical reviewer route in `approvedRoute`. Require `totalAttempts: 1`, `retryBudget: 0`, and positive integers `deadlineMs` (at most 120000), `outputBytes` (at most 65536), and `maxOutputTokens` (at most 8192). There are no budget defaults or alternate destinations. The existing SDK backend requires host-owned `authPath`, approved `sdkEntrySha256` and subscription evidence as described above; never infer API-cost permission or fabricate account attestations.

Run `node tools/reviewer-task.mjs prepare --project /absolute/project --input-sha FULL_SHA --job review.json --grant-file /external/grant.json --store /external/store` to validate without SDK loading, writes or calls. Use `run` with the same options plus `--mode real` only under the genuine provider grant. Read with `read --project /absolute/project --store /external/store --logical-job JOB_REF`. The existing private store must be outside source and target repositories. An exclusive logical-job directory prevents replay. It retains exact supplied evidence, binding, a synced invocation intent before the SDK stream and the final report/result. A partial directory remains unknown; do not remove it or retry automatically.

For runtime verification, add `workspace: {repo, probes}` to the assignment. `repo` must be a separate canonical, clean standalone checkout at the exact `candidateSha`. Each of one to three probes has `name`, `command` and `expectedExitCode`, with the same bounds as diagnostic probes. The external grant must additionally bind the identical `workspace`, `allowWorkspaceProbes: true`, `targetMode: "read-only"` and the exact `probeRunnerSha256` of `tools/diagnostic-probes.mjs`. Preparing validates these bindings without executing probes.

Running records probe intent, then uses the existing read-only diagnostic sandbox with isolated network, home and Git metadata. A probe has at most ten seconds and 8192 output bytes within the overall attempt deadline. Failed expectations, incomplete checks, dirty or mismatched checkouts, and oversized evidence block before any provider attempt. Actual observations and the candidate identity enter `workspaceVerification` in the retained evidence and binding. A failed attempt cannot be replayed. These are host-selected review-runtime observations, not commands executed or selected by the model, and do not authenticate an actor identity. Additional checks still need their own scope and grant.

The SDK receives a new opaque session ID, fixed reviewer effort, no tools, SSE, zero SDK retries, an abort signal and one-fetch maximum. Unknown errors, deadline, output limits, second fetch or nonmatching response block without retry/fallback. `response-complete` records transport completion only; report content remains untrusted and requires independent coordinator assessment. Transport completion is not a passing review or permission to replay.

## Shared execution capacity

The optional finite-capacity cut covers native reviewers, planners, diagnosticians, researchers and original worker attempts. Diagnostic admission occurs before workspace probes as well as provider work. Researcher admission reserves one slot across the logical call's existing retries and fallback route; it does not increase either budget or release an uncertain outcome. A multi-agent review panel can use distinct existing logical references for successive entries. The HTML dashboard is not an execution participant. Original workers can additionally bind prerequisites through the dependency admission contract in `docs/worker-admission.md`. Capacity is not a global scheduler or automatic dependency satisfaction.

An operator-owned pool is a separate canonical directory outside project, source and result stores. Prepare its `completed/` directory and immutable regular `policy.json` through trusted setup. The policy contains `version: 1`, a positive integer `limit` up to 16, and a nonempty `reference`. The initial approved limit is two. Capacity is separate from authorization to call a provider or create another actor.

Each participating caller's external grant must contain `capacity: {pool, policySha256}` and `capacityRunnerSha256`, the exact SHA-256 of `tools/execution-capacity.mjs`. All participating grants must bind the same pool and policy to share a limit. Omitting capacity retains the legacy path outside this guarantee. The pool is a cooperative runtime boundary, not a machine-wide service or authenticated actor registry.

The normal caller claims one directory per slot before probes or provider work. If all slots are occupied, it returns `blocked` with reason `capacity` and zero attempts/fetches, without a permanent attempt record. It can try admission again when capacity changes; that is not replaying an invocation. Complete matching provider responses move the caller's own reservation to `completed/` before publishing its result. This frees capacity even when the review remains inconclusive or the product awaits a human. It does not accept a result, integrate code or reset an actor budget.

For an original worker, pass an absolute external `--capacity-grant` to `tools/isswf-job.mjs run`. Its version-1 grant binds role `worker`, mode, project, runs store, input SHA, job path and hash, runtime SHA, attempt ID, logical job reference, grant reference, `allowCapacity: true`, capacity descriptor and helper hash. Capacity admission precedes permanent writer admission. A losing atomic admission can archive its own reservation only before either an attempt directory or job binding exists. Capacity combined with successor admission is unsupported.

Worker success does not use SDK-response completion. The lifecycle pins private helper snapshots and verifies the bound task and recorded tool PID namespaces have ceased before archiving capacity. Success JSON alone, live or mismatched identities, failure and partial evidence do not release it. Readback observes the receipt without changing capacity. Run `node tests/worker-capacity.mjs .` and `node tests/worker-capacity-api.mjs .` for portable controls. Add `--sandbox` to the API test for actual native cessation. An optional installed SDK path after the source root in the normal CLI test runs synthetic-auth offline controls without provider prompts.

Blocked, uncertain, crashed and partially published reservations stay occupied. No caller-supplied cessation boolean releases them, and there is no automatic reconciliation or cleanup. Inspect such evidence before designing or granting recovery. Permanent logical-job claims remain unchanged and cannot be reused to repeat an invocation.

## Native planner proposals

`tools/planner-task.mjs` follows the same bounded private-attempt lifecycle as the reviewer and reuses `sdkResearchBackend`. It supplies pinned `.agents/roles/planner.md`, planning guidance and durable-work ownership rules, not an external launcher. Its supported planner route is the configured Luna/high tuple with no alternate. A configuration entry is neither a grant nor evidence that an account can use the route.

Commit an assignment containing `version: 1`, `logicalJobRef`, `coordinatorRef`, canonical `targetRepo`, full `targetBase`, `briefPath`, nonempty `contextPaths`, `methodologySha`, `sdkPath` and `models: {sha, path, sha256}`. The document `inputSha` must be a full commit distinct from the target base. Brief and selected specification/grounding blobs come only from that input checkpoint, not target latest files. Supply enough evidence for the proposal; missing selected references and bundles over 64 KiB block before an attempt. Unresolved product decisions remain blockers for the coordinator.

The external grant uses `role: "planner"`, distinct external project/store/grant/auth locations, assignment/input/target hashes, `coordinatorRef`, `plannerRef`, caller/backend hashes, SDK entry digest, `approvedRoute`, `grantRef`, explicit `allowResultArtifact`, `allowProviderCalls` and `apiCostsAllowed: false`. Require `totalAttempts: 1`, `retryBudget: 0`, positive `deadlineMs <= 120000`, `outputBytes <= 65536` and `maxOutputTokens <= 8192`. Each actual call needs its own genuine grant and fresh account/subscription preflight, never a consumed reviewer grant.

Use `prepare --project /absolute/project --store /external/store --input-sha FULL_SHA --job planning.json --grant-file /external/grant.json` with the planner tool. It validates without SDK loading or writes. `run` adds `--mode real` only when specifically authorized; `read` uses project/store/`--logical-job`. Fixture execution is injected by public tests, not enabled by the real CLI. Read/prepare return `executionAuthorized: false`; a completed response is `proposal-complete` with `proposal` text. It is not adoption into `.factory/initiatives/<id>/plan.md`, implementation, verification, acceptance or execution permission. The coordinator assesses and separately records any adoption through its existing native plan command.

The caller is tool-free reasoning over supplied documents, not an executable diagnostician. Empty auth blocks before invocation; partial invocation consumes the attempt with no retry/fallback. A proposal does not establish an autonomous all-role implementation and review chain.

## Native diagnostic reports and bounded probes

`tools/diagnostic-task.mjs` reuses the shared SDK backend but adds actual host-selected probes before a text-only diagnostic report. It does not modify worker/planner/reviewer callers or give the model a shell. The explicit diagnostician route is Luna/high, no alternate; a config value does not grant a call or attest subscription availability.

Use the planner-style assignment fields with `diagnosticianRef` in the external grant and `role: "diagnostician"`. Add `probes` to the committed assignment: one to three objects containing exactly `name`, `command` (at most 2000 UTF-8 bytes, no control characters) and `expectedExitCode`. Names are unique lowercase identifiers. The job hash binds those commands; the grant additionally requires `allowWorkspaceProbes: true`, `targetMode: "read-only"` and `probeRunnerSha256` for `tools/diagnostic-probes.mjs`. Caller/backend/SDK digests, private store, finite global deadline, output/token caps, one attempt and zero retry/fallback retain their existing explicit requirements. Own diagnostician and bug-diagnosis references are pinned at `methodologySha`; brief/context are pinned at the distinct document input SHA.

`prepare`, `run --mode real` and `read` use the same argument names as the planner. Preparation reads no live probes and loads no SDK. Run claims the private logical-job directory and retains probe intent first. The target must be a clean standalone Git root at `targetBase`, with a directory `.git`; linked worktrees are not supported by this cut. Host Git cleanliness checks disable fsmonitor and untracked-cache hooks. Assigned commands run only inside Linux bwrap with target read-only, Git metadata hidden and fresh network/home/tmp/environment; runtime Node and system binaries are readonly mounts. Commands have at most ten seconds each within the global deadline and 8192 bytes combined stdout/stderr. An actual sandbox-start marker distinguishes setup failure from an observed command failure. An exit-code mismatch is diagnostic evidence, not automatic confirmed cause or a reason to rerun a model. Missing isolation, timeout, overflow or dirty/changed target blocks before model invocation and leaves inspectable records; never auto-replay.

Successful probe outputs enter the exact retained prompt/bundle hash before invocation. A returned `diagnosis-report-complete` report requires coordinator causal assessment, never implies an accepted fix, implementation permission or canonical plan update. An unavailable/missing next probe must remain unknown. The model cannot execute additional commands or inspect unseen workspace files. Selected probe commands and project contents must be appropriate for the grant and safe for the report; there is no universal secret/PII sanitizer. Pin/clean checks are not a transaction against other writers. Real callers require exclusive diagnostic use of the target.

Portable CI runs injected probe/backend controls without requiring Linux namespaces or providers. The separate `node tests/diagnostic-probes.mjs . --sandbox` and `node tests/diagnostic-task.mjs . SDK_PATH --sandbox` gates exercise actual local bwrap and the normal caller with real observations plus a synthetic backend. Installed SDK synthetic OAuth/SSE and empty-auth controls are not a live provider integration. These tests consume no real diagnostic grant.
