# Worker dependency admission

An original worker can bind an immutable canonical-plan snapshot before reserving capacity or claiming a writer. Add `prerequisites: {path, sha256, jobId}` to its committed job. The path must name `.factory/initiatives/<initiative>/plan.md` at the assignment input SHA, and `logicalJobRef` must equal `<initiative>/<jobId>`. The existing plan tool and status view share the same parser and cycle validation. No second editable plan is created.

Pass an absolute external `--dependency-grant`. Its version-1 record binds role `worker`, canonical `project` and existing `runsStore`, `inputSha`, `jobPath`, `jobSha256`, `runtimeSha`, `targetBase`, `attemptId`, `logicalJobRef`, `grantRef`, `allowDependencyCheck: true`, the identical `prerequisites` descriptor, and `attestations`. Missing or inconsistent inputs fail closed. Jobs without either dependency field retain the legacy path outside this check. Dependency-bound successors are not supported.

The attestation map covers prerequisite IDs, including transitive dependencies, and cannot name unrelated jobs. A code entry has exactly `{kind: "code", commit: "FULL_SHA"}`. The caller verifies that this operator-attested commit is an ancestor of the worker's pinned `targetBase`, with graft files and replacement objects disabled. A reported `completed` or `awaiting-human` label does not prove integration. Conversely, an explicit valid code attestation does not imply product acceptance. A decision entry has exactly `{kind: "decision", reference: "operator decision reference"}` and requires the prerequisite to be reported completed with evidence. These records use the existing cooperative, operator-owned grant boundary. They do not authenticate identities or prove who merged a commit.

An awaiting-human, blocked or in-review target job returns reason `decision`; a completed target cannot start again through this gate. Cycles, missing prerequisite evidence and unintegrated code return distinct reasons with zero attempts. The check reads committed plan bytes, not dirty replacements. A refusal creates no capacity lease, permanent writer claim, binding or attempt. A successful check only permits the later activation and existing authorization checks to proceed; it grants no provider calls, automatic acceptance or replay. The private worker binding retains the checked plan, attestations and semantic grant digest as dispatch-time evidence, not a live readiness claim.

Run `node tests/worker-dependencies.mjs .` and `node tests/initiative-dependencies.mjs .` for portable refusal and graph checks. The worker-capacity test's installed-SDK offline mode also verifies that an attested integrated dependency and an unrelated worker actually execute, while a pending decision refuses before capacity. Those synthetic-auth tests make no worker provider prompt.
